# Telegram-бот магазина X1

Прототип для тестового задания. Бот отвечает на вопросы о наушниках X1 по фиксированному регламенту. Неизвестные факты не подставляет: статус заказа выдаёт только при точном совпадении номера с локальной **демонстрационной** базой. Для запуска нужны только Python и токен Telegram-бота; внешних Python-пакетов нет.

## Запуск через Docker

Нужны Docker с Compose и токен Telegram-бота от [@BotFather](https://t.me/BotFather). Бот работает через long polling, поэтому публичный сервер и домен не нужны; контейнер должен оставаться запущенным.

```bash
cp .env.example .env
docker compose up --build -d
docker compose logs -f bot
```

Перед запуском замените `put_your_bot_token_here` в `.env` на токен своего бота. Файл `.env` исключён из Git и Docker-образа. SQLite-база хранится в Docker volume `bot_data` и сохраняется при перезапуске контейнера.

Остановить бота:

```bash
docker compose down
```

Если для этого токена ранее был настроен webhook, его нужно удалить перед long polling: [getUpdates не работает при активном webhook](https://core.telegram.org/bots/api#getupdates). Токен нельзя публиковать в репозитории или переписке.

Для запуска без Docker нужен Python 3.10+ и команда `python3 bot.py` после создания `.env`.

## Проверка без токена

Локальный режим использует тот же обработчик сообщений и такую же базу, что Telegram-бот:

```bash
python demo.py
python demo.py "доставка заказа 1842"
python -m unittest discover -s tests -v
```

## База и команды

| Файл | Содержание |
| --- | --- |
| `policy.json` | Все пункты регламента: товар, цена, доставка, возврат, брак, скидки |
| `seed_orders.json` | Три вымышленных заказа 1001–1003 |
| `demo.sqlite3` | Локальная SQLite-база, создаётся при первом запуске из `seed_orders.json`; исключена из Git. В Docker хранится в volume |
| `SYSTEM_PROMPT.md` | Текст системного промпта для подключения языковой модели |

| Команда | Ответ |
| --- | --- |
| `/start`, `/help` | Возможности и список команд |
| `/data` | Весь регламент, состав демо-базы и ограничение по заказу 1842 |
| `/orders` | Номера и статусы трёх демонстрационных заказов |
| `/order 1002` | Статус записи 1002 с явной пометкой «демонстрационный» |
| `/order 1842` | Записи нет; реальный статус неизвестен |

В обычном сообщении можно спросить о цене, наличии, доставке, возврате, браке или скидке. Если рядом со словом «заказ» указан номер, бот делает точный поиск в SQLite. Номер 1842 намеренно отсутствует, чтобы показать отказ от выдуманного статуса. Вопрос вне регламента получает ответ о нехватке данных и предложение обратиться к сотруднику.

## Как ограничены ответы

Рабочий прототип использует детерминированный обработчик `assistant.py`: он читает `policy.json` и SQLite, поэтому не зависит от платного LLM API. `SYSTEM_PROMPT.md` — готовая инструкция для будущего подключения языковой модели; нынешний обработчик не отправляет её в модель. Это разделение не позволяет выдавать текст промпта за проверенный механизм защиты. Попытки изменить правила в сообщении пользователя не меняют код или базу.

Тестовые заказы не связаны с реальными покупками. Для подключения магазина вместо `seed_orders.json` нужен авторизованный источник заказов и проверка права клиента видеть конкретный заказ.
